# LXST: аудит метрик Montserrat и заголовков

## Файлы шрифта

`node scripts/audit-montserrat.mjs` читает локальные WOFF2, таблицы `head`, `hhea`, `hmtx`, `cmap`, `fvar` и список возможностей `GPOS`. Оба файла имеют revision 9, 1000 units/em, ascender 968, descender −251, line gap 0 и переменную ось `wght` от 100 до 900 (default 100). Кириллический файл содержит 168 глифов, латинский — 322. В обоих присутствуют `kern`, `mark`, `mkmk`; метрики общих `A` и пробела согласованы: advance 688/250 units, соответственно.

Значения `hmtx` ниже относятся к **default axis 100**, поэтому для заголовков с весом 300 дополнительно измерен фактический рендеринг Chromium. Sidebearing здесь означает расстояние от начала глифа до контура, а не ширину DOM-блока.

| Глиф | `hmtx` advance / left sidebearing, units | Chromium 100px, weight 300: advance / видимый левый отступ / правое поле, px | Видимый левый отступ при 400, px |
| --- | ---: | ---: | ---: |
| В | 752 / 137 | 75 / 12 / 7 | 11 |
| с | 548 / 62 | 55.7 / 5 / 3.7 | 4 |
| Т | 556 / 8 | 57.5 / 0 / 0.5 | 0 |
| А | 716 / 23 | 73.3 / 1 / 1.3 | 1 |
| П | 833 / 137 | 82.8 / 12 / 11.8 | 11 |
| О | 857 / 69 | 85.3 / 5 / 5.3 | 5 |
| И | 826 / 137 | 82.5 / 12 / 11.5 | 11 |
| Latin T | 548 / 4 | 56.3 / 0 / −0.7 | 0 |

`node scripts/audit-montserrat.mjs --browser` повторяет браузерные измерения через локальный Chromium CDP на порту 9225. Требуются запущенный Chromium с `--remote-debugging-port=9225` и Vite на `http://127.0.0.1:5173/`; порт и URL можно заменить переменными `LXST_CDP_PORT` и `LXST_DEV_URL`. Canvas измеряется с `textAlign=left`, `fontKerning=normal`, после `document.fonts.ready`. `inkStart = -actualBoundingBoxLeft`, `rightBearing = width - actualBoundingBoxRight`. Оба `@font-face` в проверенном браузере были `loaded`, объявлены с диапазоном весов 100–900. Заголовки имели вычисленный вес 300, `font-kerning: normal`, `font-synthesis: none`, `font-feature-settings: normal`, `font-variation-settings: normal`: признаков fallback или синтетического начертания не обнаружено.

## Диагноз и поправки

Сравнение Canvas `fontKerning=normal` и `none` при 100px/300 показывает работающий кернинг: «стр» 168.50 против 169.70px, «Все» 190.67 против 191.60px, «Тв» 116.27 против 117.70px. Для «тво», «для», «Во» ширины совпали. Латинское `To` отличается на 5.5px. Следовательно, кернинг не отключён. Главная причина разного начала строк — боковые поля первых глифов: «В» и «П» начинаются на 12px позже начала строки, «с» — на 5px, «Т» — без видимого отступа. Предыдущее общее tracking `−0.008em` дополнительно делало плотные пары визуально тесными.

Display tracking ослаблен до `−0.004em`, tracking заголовков разделов — до `−0.002em`; Montserrat Light 300 сохранён. В домашнем заголовке первая строка целиком получает разницу боковых полей `0.05em − 0.12em = −0.07em`. На широких экранах весь заголовок смещён на `−0.02em`, чтобы видимый край двух строк совпал с описанием. При размере заголовка 89.28px это даёт `−6.25px` и `−1.79px`: видимое начало обеих строк находится примерно в 2.68px от сетки, описание — в 2.49px. При 360px широкое смещение не применяется: видимое начало строк — около 1.7px, описания — около 2.04px.

Заголовки авторизации и кабинетов используют общую формулу `text-indent: calc(var(--ui-copy-ink-start) - var(--ui-title-ink-start))`. Для начальных «П»/«В» `--ui-title-ink-start: 0.12em`; сопроводительный текст имеет измеренный видимый край 0.02em/0.03em. Это поправка только первой строки, поэтому последующие переносы сохраняют естественное положение. Контейнеры и сетка проверялись до применения смещения. Другим заголовкам поправка не потребовалась. Вес 400 делает штрихи плотнее, но уменьшает левый отступ «В»/«П» всего на 1px при 100px; как общая замена он не решает расхождение.

Разделение домашнего текста на обычный фрагмент и фиолетовый `em` не меняет ширину строки: при 1440px измеренные ширины слитного текста и разметки с `em` обе равны 673.484px. На широких экранах остаются строки «Всё для твоего» / «стрима», светло-фиолетовыми остаются только «твоего стрима».

## Визуальная проверка

Снимки до и после сделаны в одном headless Chromium. Главная, `/overlay` и авторизация открыты как страницы приложения. Кабинеты стримера и модератора рендерились из настоящих React-компонентов через локальные статические фикстуры, поскольку полный вход требует Twitch OAuth. Во время снимков Vite работал без сервера API; сообщения о недоступности API на страницах не относятся к изменению типографики.

Автоматическая проверка после загрузки шрифта охватила 5 маршрутов/фикстур × 6 базовых ширин (360, 390, 768, 1024, 1440, 1920px) × 4 масштаба (100%, 125%, 150%, 200%) = 120 случаев. Масштаб эмулировался изменением доступной CSS-ширины и device scale factor; это не команда браузерного меню Zoom. Проверялись ширина документа и обрезание `h1`/`h2`. Во всех 120 случаях горизонтального переполнения и обрезания заголовков не обнаружено. Снимки подтверждают ровный левый край, переносы и отсутствие видимого слипания букв на указанных экранах. Реальный OBS Browser Source и живой кабинет после Twitch OAuth требуют ручной проверки в пользовательской среде.

## Защита от регрессии

`scripts/check-typography.mjs`, включённый в `npm run lint`, отклоняет display/section tracking сильнее `−0.005em` в общих токенах и правилах крупных заголовков. Размеры мелкого текста, OBS-холст, приложение и серверная логика в этой правке не изменены.
