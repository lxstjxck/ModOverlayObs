# Windows staging: playback OBS и редактора

## YouTube IFrame API: staging smoke

Автоматическая проверка: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `node scripts/smoke-playback.mjs` и `node scripts/smoke-youtube-adapter.mjs`. Их PASS подтверждает контракты и сборку, но не реальное воспроизведение в OBS.

PENDING в настоящем OBS Browser Source (staging, отдельные SQLite/uploads/токен):

1. Откройте обычное YouTube-видео 1–5 минут через `watch`, `youtu.be` и Shorts. Проверьте PLAYING, PAUSED, BUFFERING, ENDED, фактический таймкод и отсутствие перезагрузки iframe при изменении геометрии, громкости и Loop.
2. Включите Loop, дождитесь конца и проверьте повтор. Выключите и включите Loop во время воспроизведения: картинка и звук не должны прерываться. Проверьте Play, Pause, Stop, Restart и Seek с подтверждением таймкода OBS после каждой команды.
3. Остановите staging Node.js на 15–20 секунд. Видео и Loop должны продолжаться. После запуска и reconnect редактор должен показать фактический таймкод без повторного Restart, Seek или Play. Полный перезапуск OBS проверьте отдельно: новый iframe должен принять текущую сцену.
4. Подключите два OBS Browser Source одного канала и убедитесь, что в селекторе отображаются отдельные позиции. Проверьте два канала с разными видео: телеметрия не должна пересекаться.
5. Проверьте удалённое/приватное видео, запрет встраивания, отсутствие сети, долгую буферизацию и блокировку autoplay. Ошибка должна отображаться в панели; другие элементы сцены продолжают работать.
6. Для YouTube Live проверьте поведение `duration` и Seek отдельно: Player API возвращает время с начала трансляции, а не конечную длительность, и перемотка может быть недоступна.

Используйте отдельную staging SQLite, каталог uploads и тестовый OBS-токен. Production `.env`, базу, VPS и реальные OBS-токены не меняйте. Перед ручной проверкой выполните `npm run typecheck`, `npm run lint`, `npm test`, `npm run build` и `node scripts/smoke-playback.mjs` для собранных артефактов. Этот smoke проверяет сборку телеметрии; работу сети и браузера проверяют интеграционные тесты и ручной сценарий ниже.

1. Откройте HTML5 MP4 в OBS Browser Source и редакторе. Запустите видео с Loop; убедитесь, что панель показывает ID конкретного OBS и его таймкод, а не время локального предпросмотра.
2. Остановите staging Node.js через Ctrl+C на 10–20 секунд. Видео и Loop в OBS должны продолжаться. В редакторе должен появиться OFFLINE; таймкод не должен выдаваться за актуальный.
3. Запустите тот же staging Node.js. После reconnect видео в OBS должно продолжиться с текущей позиции без Restart, Seek и Play. В редакторе должен появиться фактический таймкод OBS.
4. После reconnect проверьте Pause, Seek, Play, Stop и Restart. Для каждой команды сравните фактическое состояние OBS с таймкодом, состоянием PLAYING/PAUSED и подтверждённым ID команды в редакторе. Повторный snapshot не должен исполнять команду второй раз.
5. Откройте второй OBS Browser Source этого же канала на другой позиции. Переключите источник в панели и проверьте оба таймкода отдельно. Закройте один OBS: его статус должен исчезнуть. Для другого канала телеметрия не должна появляться.
6. На тестовом канале отзовите OBS-токен. Старый источник должен очистить сцену и отключиться; его статус должен исчезнуть из редактора. Новый токен должен работать после открытия нового Browser Source.

Отдельно проверьте локальные загруженные видео и внешние HTML5 URL, seek/start-time, mute, volume, Loop, cleanup и reload. YouTube в панели помечается как локальный preview: HTML5-телеметрия OBS для iframe недоступна.
